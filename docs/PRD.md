## 1. 개요

My Tasks는 개인이 할 일을 기록하고, 카테고리로 나누고, 진행 상황을 한눈에 확인하는 웹 앱이다. 데이터는 사용자의 브라우저(localStorage)에만 저장되며, 파일 내보내기·가져오기로 백업과 이동을 지원한다. 한 화면 구성이 데스크톱(3단)부터 휴대폰(1단)까지 화면 크기에 맞춰 바뀐다.

### 1.1 배경
- 처음에는 모바일에 맞춘 600px 카드 하나짜리 화면으로 시작했다.
- 데스크톱에서 화면이 넓어도 가운데 좁은 카드만 쓰는 문제가 확인되었다.
- 그래서 전체 화면을 활용하는 반응형 레이아웃으로 통합했다.

### 1.2 목표
1. 할 일을 **빠르게 입력하고** 정리할 수 있다 (Enter 한 번, 카테고리 자동 분류).
2. **진행 상황을 즉시** 확인하고 동기를 얻는다 (진행률, 응원 메시지, 격언).
3. 실수해도 **데이터를 잃지 않는다** (실행 취소, 최근 삭제 보관, 백업 파일).
4. 데스크톱·태블릿·휴대폰 **어디서나 편하게** 쓴다 (반응형, 터치, 키보드).
5. 키보드·스크린 리더 사용자도 **모든 기능을 쓸 수 있다** (접근성).

### 1.3 비목표 (이번 범위 밖)
- 계정, 서버 동기화, 여러 기기 간 실시간 공유
- 마감일·알림·반복 일정
- 하위 할 일, 첨부 파일, 협업
- 다중 선택 일괄 작업, 카테고리로 끌어 옮기기, 우클릭 메뉴 → [TASK.md 백로그](TASK.md#3-백로그-남은-작업)

## 2. 사용자

| 사용자 | 특징 | 핵심 요구 |
|---|---|---|
| 직장인·학생 | 업무·개인·공부 할 일이 섞여 있음 | 빠른 입력, 카테고리 구분, 진행률 |
| 데스크톱 사용자 | 넓은 모니터, 키보드 위주 | 화면 전체 활용, 단축키, 키보드 탐색 |
| 휴대폰 사용자 | 좁은 화면, 터치 | 큰 터치 영역, 1단 레이아웃 |
| 보조 기술 사용자 | 스크린 리더, 키보드만 사용 | ARIA 레이블, 포커스 관리, 상태 안내 |

## 3. 기능 요구사항

우선순위: **P0** 필수 · **P1** 중요 · **P2** 부가

### 3.1 할 일 기본 (P0)
| ID | 요구사항 |
|---|---|
| F-01 | 입력창에 할 일을 쓰고 **Enter 또는 추가 버튼**으로 추가한다. 앞뒤 공백은 제거하고, 빈 입력은 거부한다(입력창 흔들림 + 안내). |
| F-02 | 각 할 일의 **체크박스**로 완료/미완료를 바꾼다. 완료 항목은 **취소선**과 흐린 색으로 표시한다. |
| F-03 | 각 할 일의 **× 버튼**으로 삭제한다. |
| F-04 | 각 할 일의 **연필(수정) 버튼**으로 그 자리에서 내용과 카테고리를 수정한다. Enter 저장, Esc 취소, 편집 영역 밖을 누르면 저장. 빈 내용으로 저장하면 취소로 처리한다. |
| F-05 | 할 일은 `{ id, text, completed, createdAt, category }`로 저장되며, 새로고침해도 유지된다. |
| F-06 | 할 일 최대 길이 200자, 최대 개수 1000개. 넘으면 안내한다. |

### 3.2 카테고리 (P0)
| ID | 요구사항 |
|---|---|
| F-10 | 카테고리는 **업무(work)·개인(personal)·공부(study)** 3가지다. |
| F-11 | 추가할 때 드롭다운으로 카테고리를 고른다. |
| F-12 | 각 할 일에 카테고리 색 태그를 표시한다: 업무 `#4A90E2`, 개인 `#27AE60`, 공부 `#8E44AD`. |
| F-13 | 필터(전체·업무·개인·공부)로 목록을 거른다. 선택된 필터를 강조하고, 선택 상태는 저장한다. 데스크톱 메뉴에는 카테고리별 개수를 표시한다. |
| F-14 | 카테고리 필터를 보고 있으면 새 할 일의 기본 카테고리도 그 카테고리가 된다. |

### 3.3 키워드 자동 분류 (P1)
| ID | 요구사항 |
|---|---|
| F-20 | 입력하는 동안 키워드로 카테고리를 추정해 드롭다운을 자동으로 바꾸고, 근거를 보여 준다. 예: `🏷 "영어", "단어" → 공부로 자동 분류했어요` |
| F-21 | 사용자가 카테고리를 **직접 고르면** 그 할 일을 추가할 때까지 덮어쓰지 않는다. 키워드가 다른 카테고리를 가리키면 **제안만** 표시한다. |
| F-22 | 판단이 애매하면(동점) 분류하지 않는다. 키워드를 지우면 원래 카테고리로 돌아간다. |
| F-23 | 카테고리가 없는 파일을 가져올 때도 같은 규칙으로 분류하고, 몇 개를 분류했는지 알린다. 이미 저장된 할 일은 다시 분류하지 않는다. |

### 3.4 정렬·검색 (P1)
| ID | 요구사항 |
|---|---|
| F-30 | 정렬: **완료 상태순(기본, 완료 항목은 아래)**, 생성일순(최신 먼저), 카테고리순, 직접 정렬. 선택은 저장한다. |
| F-31 | 손잡이를 **드래그**해 순서를 바꾼다(마우스·터치). 화면 끝에서 자동 스크롤, Esc로 취소. 손잡이에서 ↑/↓ 키로도 옮긴다. |
| F-32 | 생성일순에서 순서를 옮기면 "직접 정렬"로 전환한다. 완료 상태순·카테고리순에서는 같은 그룹 안에서만 옮겨지고, 그룹을 넘기면 안내한다. |
| F-33 | 검색창 입력에 따라 목록을 실시간으로 거른다(대소문자 무시, 필터와 함께 적용). 일치 부분을 강조하고, 결과 수를 스크린 리더로 알린다. Esc로 검색어를 지운다. |

### 3.5 진행률·동기 부여 (P1)
| ID | 요구사항 |
|---|---|
| F-40 | 전체 진행률을 `5/10 완료 (50%)` 형식과 프로그레스 바로 보여 준다. |
| F-41 | 카테고리별 미니 진행률(완료/전체)을 보여 준다. |
| F-42 | 오늘 추가된 할 일 개수를 보여 준다(자정이 지나면 갱신). |
| F-43 | 제목 옆 배지로 남은 할 일 개수를 보여 준다. 모두 완료하면 색이 바뀐다. |
| F-44 | 완료율 구간에 따라 응원 메시지를 보여 주고, 마지막 할 일을 완료하면 축하 알림을 띄운다. |
| F-45 | 오늘의 격언을 보여 준다(하루 동안 같은 격언). 새로고침 버튼으로 다른 격언을 본다. |
| F-46 | 모든 수치는 추가·삭제·완료·수정 즉시, 그리고 다른 탭에서 바뀌어도 반영한다. |

### 3.6 데이터 보호 (P0)
| ID | 요구사항 |
|---|---|
| F-50 | 삭제 후 알림의 **실행 취소** 버튼으로 되돌린다. 원래 위치에 복구한다. |
| F-51 | **최근 삭제** 목록에서 지난 7일·최대 50개 항목을 개별 복구하거나 영구 삭제한다. 텍스트 입력 중이 아닐 때 **Ctrl+Z**로 마지막 삭제를 복구한다. |
| F-52 | **완료된 항목 모두 삭제**: 개수를 보여 주고 확인 창을 거친다(모든 카테고리 대상임을 안내). |
| F-53 | 같은 내용(공백·대소문자 무시)의 할 일이 있으면 입력 중 경고하고, 추가할 때 확인 창으로 한 번 더 묻는다. |
| F-54 | **내보내기**: 전체 할 일을 JSON 파일로 내려받는다. |
| F-55 | **가져오기**: JSON 파일을 검증한 뒤 확인 창에서 "바꾸기/합치기"와 "가져오기 전 현재 데이터 백업"(기본 체크)을 고른다. 가져온 뒤에도 실행 취소할 수 있다. 잘못된 파일은 이유를 알려 거부하고, 잘못된 항목은 건너뛴 개수를 알린다. |
| F-56 | 저장된 데이터가 손상되었으면 원본을 따로 보관하고 빈 목록으로 시작한다고 알린다. 저장 공간 부족이나 저장소 사용 불가도 안내한다. |

### 3.7 테마 (P1)
| ID | 요구사항 |
|---|---|
| F-60 | 화면 오른쪽 위의 스위치로 다크/라이트 모드를 바꾼다. 선택은 저장하고, 고른 적이 없으면 운영체제 설정을 따른다. |
| F-61 | 다크 모드 색: 배경 `#1A1A1A`, 카드 `#2D2D2D`, 텍스트 `#E0E0E0`. 전환은 부드럽게, 첫 화면 깜빡임 없이. |

### 3.8 키보드 (P1)
| 키 | 동작 |
|---|---|
| Alt+N | 새 할 일 입력창으로 |
| Alt+1~4 | 필터: 전체·업무·개인·공부 |
| Alt+D | 다크 모드 전환 |
| / | 검색창으로 |
| Ctrl+Z | 마지막 삭제 복구 (입력창 밖에서) |
| ↑ / ↓ · Home / End | 목록 항목 사이 이동 · 처음/끝 |
| Space · Enter · Delete | 완료 체크 · 수정 시작 · 삭제 |
| 검색창에서 ↓ | 첫 검색 결과로 |

한글 입력 상태에서도 단축키가 동작해야 한다.

### 3.9 피드백 (P1)
모든 동작에 피드백을 준다: 하단 알림(토스트), 항목 추가 시 나타나는 효과, 삭제 시 사라지는 효과, 완료 시 슬라이드, 수정 저장 시 잠깐 강조, 진행률 바 전환, 버튼 눌림 효과.

## 4. 화면 요구사항 (반응형)

| 화면 너비 | 구성 |
|---|---|
| 1280px 이상 | **3단**: 왼쪽 메뉴(제목·배지, 카테고리, 데이터, 단축키) · 가운데 목록(최대 1040px) · 오른쪽(테마 스위치, 격언, 진행률) |
| 900~1279px | **2단**: 왼쪽 메뉴 · 오른쪽 위 격언·진행률, 그 아래 목록 |
| 899px 이하 | **1단**: 제목 → 격언 → 진행률 → 카테고리 버튼 → 입력·목록 → 데이터 버튼 |
| 480px 이하 | 1단 + 터치 영역 44px 이상, 입력 폼 줄바꿈 |
| 높이 820px 이하 (2·3단) | 사이드바 간격 축소, 단축키 목록은 접힌 상태로 시작 |

- 900px 기준은 1366px 노트북을 150% 배율로 쓰는 경우(약 910px)에도 2단이 되도록 정했다.
- 넓은 화면에서 카테고리 태그·시간은 할 일 내용 바로 뒤에 붙는다(눈이 멀리 오가지 않도록).
- 목록을 스크롤해도 양옆 패널은 고정된다.

## 5. 비기능 요구사항

| 구분 | 요구사항 | 현재 수준 |
|---|---|---|
| 성능 | 100개 이상에서도 부드러움. 완료 체크·검색이 한 프레임(16ms) 안에 처리 | 1000개: 완료 체크 14.7ms, 검색 2.3ms |
| 저장 | 연속 변경은 묶어서 저장(디바운스), 페이지를 떠날 때 즉시 저장 | 300ms 디바운스 + 페이지 이탈 시 저장 |
| 접근성 | ARIA 레이블, 포커스 관리, 스크린 리더 안내, 동작 줄이기 설정 존중 | 적용 (실제 스크린 리더 확인은 미완) |
| 보안 | 사용자 입력을 HTML로 해석하지 않음 (XSS 방지) | 텍스트 노드로만 삽입 |
| 호환성 | 최신 Chrome·Edge·Safari·Firefox, 빌드 없이 파일로 실행 | 헤드리스 Edge로 검증 |
| 오프라인 | 네트워크 없이 동작 | 외부 리소스 없음 |

## 6. 성공 기준

- 핵심 흐름(추가 → 완료 → 삭제 → 복구 → 내보내기/가져오기)이 오류 없이 동작한다.
- 1366×768 노트북부터 2560px 모니터까지 가로 스크롤과 겹침 없이 화면을 채운다.
- 키보드만으로 모든 기능을 쓸 수 있다.
- 자동 검증 163개 항목이 모두 통과한다 ([TRD §10](TRD.md#10-테스트-전략)).

## 7. 열린 이슈

| 이슈 | 상태 |
|---|---|
| Alt+D가 Edge·Chrome의 "주소창으로 이동" 단축키와 겹칠 수 있음 | 실제 키보드로 확인 필요 |
| 480px 이하 휴대폰 화면 | 실제 기기 또는 개발자 도구로 확인 필요 |
| 스크린 리더(NVDA 등)로 실제 읽기 | 확인 필요 |
| 카테고리 메뉴 숫자가 "전체 개수"인지 화면에 표시되지 않음 | 개선 검토 |
